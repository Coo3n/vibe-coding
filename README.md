# День 15 · Устаревание и конфликты памяти

Агент для планирования поездки обновляет актуальные факты, ведёт журнал замен и очищает данные текущей задачи после завершения. Интерфейс сохраняет меню, цветные панели и команды просмотра слоёв из Lab11. Лабораторная запускается отдельно от Lab11–14.

## Запуск

Из каталога `Lab15` на macOS или Linux с Python 3.9+.

```bash
python -m pip install -r requirements.txt
python main.py
python main.py --demo
python main.py --chat
python main.py --demo --codex
python main.py --chat --codex
python main.py --show-results results/experiment-1
python main.py --show-results results/terra-1
```

Чат и эксперимент по умолчанию работают с локальным клиентом. Режим `--codex` отправляет подготовленные сообщения через установленный Codex CLI со входом в ChatGPT. Модель по умолчанию — `gpt-6.1-terra`, её можно заменить через `--model`. Программа ищет команду `codex` в PATH и в составе ChatGPT.app на macOS. Для обычного API есть отдельный режим `--live`. Он берёт `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL` из окружения либо `.env` в корне репозитория. Поддерживаются имена переменных из Lab11 `API_URL`, `API_TOKEN`, `MODEL`.

## Диалог

```text
/remember срок: 20 марта
Какой сейчас срок?
Срок переносим на 27 марта.
Какой сейчас срок?
/remember решение: Сверить правила перевозки багажа.
/note черновик: Проверить пересадки в воскресенье.
/context
/log
/done
Что сохранено про «черновик»?
Какой сейчас срок?
```

Поддерживаемые фразы обновляют поля `срок`, `статус`, `требование`, `подход` и `версия`. Примеры — «Статус теперь подтверждено», «Требование отменили», «Выбрали другой подход: поезд и ночной автобус», «Версия теперь 2.0». Произвольные данные можно записать через `/remember ключ: значение` и запросить фразой `Что сохранено про «ключ»?`. Команда `/forget ключ` удаляет долговременный факт. Просмотр доступен через `/layers`, `/short`, `/working`, `/long`, `/history`, `/log` и `/context`. `/context` показывает сообщения, подготовленные для следующего запроса, к которым добавится текущий вопрос. Для чата с пустой базой укажите `--memory-file путь.json`.

## Правила памяти

| Данные | Запись | Что попадает в промпт |
|---|---|---|
| Актуальные долговременные факты | Одно значение и время в UTC на ключ. Более поздняя запись заменяет предыдущую. При равенстве времени остаётся уже сохранённая запись. | Ключи и текущие значения |
| Решения и история изменений | `/remember решение: …` и `/remember история изменений: …` добавляют записи с отметками времени. Журнал автоматически фиксирует предыдущее и новое значения при замене и предыдущее при удалении. | Актуальные данные извлекаются из отдельного набора фактов. Накопительные записи и журнал доступны через команды просмотра. |
| Рабочие данные задачи | `/note` создаёт временную запись. `/done` удаляет все такие записи и сбрасывает видимое модели окно. | Рабочие значения, если ключ свободен в долговременной памяти |
| Реплики | `/history` показывает диалог до `/reset`. Изменение сохранённых данных сбрасывает отсчёт окна реплик, доступных модели. | Текущий вопрос и окно реплик после последнего обновления |

Удаление сохраняет временную отметку ключа, поэтому запоздалая запись не восстанавливает удалённый факт. В свежем свободном тексте маскируются буквальные упоминания снятых значений, пока эти значения нигде не актуальны. Проверка охватывает сохранённые строки. Смысловые перефразировки свободного текста требуют отдельной проверки.

Долговременная память чата хранится в `data/memory.json`. При запуске до первой записи используется исходный набор Lab11 с учебными отметками времени из `data/long_term_seed.json`. `/clear long` очищает актуальные и накопительные записи и сохраняет журнал. `/reset` запускает новый диалог с сохранённой долговременной памятью. Запись на диск происходит атомарно под файловой блокировкой.

## Эксперимент

Демо работает в отдельном временном хранилище и задаёт один и тот же вопрос по каждому полю до и после изменения. Перед первой репликой консоль показывает исходные факты, накопительные решения, рабочую заметку и число сообщений в краткосрочной памяти. Исходные данные также записываются в отчёты. Консоль печатает каждую реплику перед обработкой, затем показывает ответ или подтверждение операции с памятью. Сводка появляется после диалога. После каждого обновления проверяется ответ и полный запрос, переданный клиенту. Дополнительно сценарий проверяет запоздалую и равную по времени запись и завершает задачу.

В [офлайн-отчёте](results/experiment-1/report.md) локальный клиент дал 4 из 4 актуальных ответов. Среди четырёх ответов и четырёх промптов было ноль устаревших значений. Журнал содержит четыре замены, а рабочая память после завершения сократилась с одной записи до нуля. На диске сохранились актуальные факты, накопительные решения и журнал.

В режиме Codex отчёт показывает токены входа и выхода по завершённым ходам. Четыре обновления фактов, две проверки времени записи и очистка рабочей памяти — семь операций приложения, которые выполняются без вызовов модели.

В [прогоне Terra](results/terra-1/report.md) модель дала 4 из 4 актуальных ответов. Устаревших значений в четырёх контрольных ответах и промптах было ноль. После завершения Terra ответила «Нет актуальной записи» на вопрос о рабочей заметке, а долговременный снимок сохранился без изменений. Codex CLI сообщил 128 446 входных и 89 выходных токенов за 10 ходов. Входной расход включает контекст Codex CLI.
