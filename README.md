# День 6 · Квартирный агент «Ключ»

**Видео:** [демонстрация работы агента](results/demo.mov).

Python CLI с LLM tool calling: **300 учебных квартир в СПб**, вымышленный банк «Нева», модель **glm-53-flash** через маршрут `coder`. Квартиры и финансирование не настоящие.

## Запуск

Python **3.10+**, macOS/Linux. Из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

В локальном `.env` нужны:

```dotenv
LLM_API_URL=https://your-api.example/api/v1/chat/completions
LLM_API_KEY=your-key
LLM_MODEL=coder
```

Нужен OpenAI-совместимый API с поддержкой `tools`. Существующий `.env` перезаписывать не нужно; переменные окружения имеют приоритет.

```bash
python main.py           # свободный чат: /new — новый подбор, /exit — выход
python main.py --demo    # все три кейса
python main.py --case 1  # общий вопрос без инструментов
python main.py --case 2  # поиск квартиры до подходящей цены
python main.py --case 3  # поиск квартиры до полного финансирования банком
```

В кейсах 2–3 агент проверяет результат функций и продолжает подбор, если подходящей квартиры ещё нет. Порядок инструментов выбирает модель. Повторные вызовы разрешены; в свободном чате программная проверка цели не включена.

## Инструменты и LLM-запросы

- **`choose_apartment(max_price?)`** — случайная непросмотренная квартира. Цена выше **15 млн ₽** → отсев до банка.
- **`check_mortgage(apartment_id)`** — случайный лимит от цены самой дешёвой квартиры до **15 млн ₽**; проверяет, хватит ли денег на выбранную квартиру. Лимит не меняется до нового подбора.

```text
Пользователь → LLM → tool_calls → Python-функция
                  ↑                   ↓
                  └── результат ──────┘
                  → ответ пользователю, когда инструменты больше не нужны
```

Каждая стрелка к LLM — отдельный HTTP-запрос с историей. Обычно без инструментов — **1 запрос**, с одним вызовом инструмента — **2**, с двумя последовательными — **3**. Отдельного запроса для форматирования нет. Используются `tool_choice: auto` и `parallel_tool_calls: false`.

Промпт только: **«Ты помогаешь выбрать квартиру. Данные учебные.»** Порог цены заранее не сообщается ни в запросах кейсов, ни в схемах: модель узнаёт ограничения из результатов функций. Квартиры и лимит банка случайны при каждом запуске, внутри подбора квартиры не повторяются.

Ошибки аргументов возвращаются модели. Исчерпание вариантов, три шага без прогресса или ошибка API завершают подбор с явной ошибкой. Общий предохранитель — **605 HTTP-шагов** для каталога из 300 квартир.

## Консоль и результаты

Цветные вложенные рамки разделяют запрос, параметры, результат инструмента и итоговую сводку вызовов. Во время ожидания видны таймер и процент **от сетевого таймаута 120 с**, а не готовность ответа. В интерактивном терминале ввод во время обработки отбрасывается.

**PyCharm:** используйте вкладку **Terminal** либо включите **Emulate terminal in output console** в конфигурации запуска.

**[Протокол контрольного прогона](results/demo.json)** содержит реальные ответы API, аргументы и результаты функций, время, `usage` и проверки кейсов. Новые прогоны сохраняются в игнорируемые `results/local-*`; `--output-dir` задаёт другую новую папку. Код выхода демо: `0` — все кейсы прошли, `1` — есть ошибки. Текст ответа проверяется вручную; автотесты не добавлены по просьбе пользователя.

## Структура

`main.py` — запуск; `app/agent.py` — агентный цикл и проверка цели; `app/client.py` — HTTP и настройки; `app/tools.py` — функции и схемы; `app/cli.py` — консоль и кейсы; `data/apartments.json` — каталог; `results/` — ролик и контрольный протокол.

`.env`, ключи, виртуальное окружение, IDE и временные прогоны исключены из Git. Для `coder` задано сообщённое пользователем имя `glm-53-flash`; конкретное имя из API имеет приоритет. Служебный `GET /models` выполняется один раз при запуске и не считается генерацией LLM.
