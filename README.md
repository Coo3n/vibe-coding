# Температура LLM: точность или разнообразие?

**Есть видео запуска:** [посмотреть запись эксперимента](results/demo.mp4).

**Результаты:** [отчёт с ответами и выводами](results/temperature-glm.md) · [исходные данные JSON](results/temperature-glm.json).

Эксперимент на **WB `coder` → `glm-53-flash`**: одна и та же задача и один творческий запрос при `temperature = 0`, `0.7`, `1.2`. Каждая комбинация повторяется **5 раз — 30 экспериментальных вызовов**. Во всех них одинаково запрошен **`reasoning_effort=medium`**. Затем **31-й вызов** анализирует все ответы с `high`.

> **Важно:** WB принимает `temperature=1.2` и `reasoning_effort=medium`, но [документация GLM](https://docs.z.ai/api-reference/llm/chat-completion) указывает диапазон температуры **0–1** и effort **low/high/max**. По вашему выбору отправляются именно значения из ТЗ и `medium`, без подмены. Фактическое применение 1.2 без обрезки и трактовка medium шлюзом не подтверждены. До подтверждения WB результаты показывают наблюдаемые различия ответов, а не доказанный эффект этих настроек. Это ограничение указано и в отчёте, и во входных данных ИИ-разбора.

| Запрос | Ожидаемый результат | Что проверяем |
|---|---|---|
| Резервуар | `{"answer":690}` | Правильность числа, JSON и повторяемость |
| Бытовые привычки | `{"ideas":["…"]}` | Одна краткая идея ролика, формат и разнообразие |

**Точная задача:** первая труба заполняет резервуар за 12 часов, вторая — за 18, слив опорожняет за 36. Изначально заполнена треть. Открывают обе трубы и слив, через 2 часа закрывают первую трубу, ещё через 3 часа — слив. Вторая труба работает до заполнения. Найти общее время в минутах. **Эталон: 690 минут**: после первых двух этапов заполнено 23/36, оставшиеся 13/36 заполняются за 6.5 часа; всего 11.5 часа. Эталон не передаётся в экспериментальных запросах.

**Творческий запрос:** одна оригинальная идея короткого юмористического ролика про бытовые привычки — узнаваемая ситуация и смешной поворот, до 15 слов.

## Запуск

Нужен Python **3.10+**, дополнительных библиотек нет. В `.env` рядом с `main.py`:

```dotenv
LLM_API_KEY=ваш_ключ
LLM_API_URL=https://api.example.com/v1/chat/completions
LLM_MODEL=coder
```

```bash
python main.py
```

Скрипт автоматически отправляет запросы, показывает полные ответы, проверки и число скрытых токенов рассуждения из `usage`. В **30 экспериментальных запросах** `reasoning_effort=medium` одинаков, меняется только температура. Числовой бюджет рассуждений, `max_tokens` и seed **не задаются**. Требование краткости есть только в промпте. Принудительная JSON Schema не используется: нарушения формата — часть эксперимента. WB-маршрут берётся из `.env`; фактическая модель проверяется с первого ответа и должна оставаться `glm-53-flash`.

Если API сообщает ноль скрытых токенов, скрипт предупреждает, но не останавливается. Отсутствие `reasoning_tokens` показывается отдельно, а не подменяется нулём. Успешный запрос не доказывает, что провайдер применил `medium` именно так, как ожидается.

Итоговый ИИ-разбор — **отдельный запрос той же модели с `reasoning_effort=high`**, вне статистики температур. Он получает все ответы и измерения, оценивает смысловые повторы, юмор и полезность разнообразия, приводит конкретные примеры и рекомендации. Это субъективная самооценка: она не исправляет счётчики и не заменяет эталон 690.

## Результаты и видео

После запуска появятся:

- **`results/temperature-glm.md`** — таблица, примеры всех ответов, повторяемость при нулевой температуре и итоговый ИИ-разбор.
- **`results/temperature-glm.json`** — промпты, отправленные параметры, ответы, фактический ID модели, `usage`, время, проверки и отдельный объект `analysis`.

В `results/` сохранён прогон GLM с задачей о резервуаре и одной идеей про бытовые привычки. Изменения кода применяются только при **новом запуске**; уже работающий процесс не меняется.

Для отдельного запуска: `python main.py --output results/another-run.json`. Во время работы сохраняются `*.partial.json` и `.md`; при сбое или смене модели они остаются для диагностики. Итоговые файлы публикуются парой после 30 ответов и попытки ИИ-разбора. Если разбор не удался, сами 30 результатов сохраняются с `analysis.status=failed` — без выдуманного заключения. Автоматических повторов и незаметной подмены параметров нет. При ошибке записи восстанавливаются предыдущие файлы; после аварийного завершения процесса резервные копии могут остаться в `results/.report-staging-*`.

**Видео:** запись запуска находится в [`results/demo.mp4`](results/demo.mp4).

## Проверка кода

```bash
python -m unittest discover -v
```

Тесты проверяют формат одной идеи и оценку ответа математической задачи. Запросы к API не выполняются.

## Как читать сравнение

- **Формат и точность отдельно.** Неверное число, неправильный JSON и сбой API не смешиваются. Ответ другой модели или повреждённый API-конверт сохраняются как исключённые из сравнения. Нечитаемый ответ не засчитывается как правильный; для идей автоматически проверяются структура, число строк и длина.
- **Повторы всего ответа** считаются посимвольно. Разные валидные JSON считаются без влияния пробелов между полями и порядка ключей; порядок идей при этом важен.
- **Повторы отдельных идей** считаются среди валидных ответов после нормализации регистра и пробелов. Перефразировка одной шутки может выглядеть уникальной: качество юмора, тематическую уместность и смысловую новизну нужно оценить по примерам.
- **`temperature=0` не обещает идентичности.** Отчёт покажет, совпали ли именно эти пять повторов. Даже полное совпадение не гарантирует его в будущем; WB API может также игнорировать настройку.

Обычно **0** — отправная точка для точных задач, **0.7** — для вариантов текстов и идей, **1.2** — для более широкого мозгового штурма на моделях, поддерживающих это значение. Для GLM через WB действие 1.2 пока не подтверждено. Это ориентиры, а не заранее известные результаты. Пять повторов на двух запросах не доказывают общего превосходства температуры.

## Сверка с ТЗ

| Требование | Реализация |
|---|---|
| Температуры 0 / 0.7 / 1.2 | Отправляются буквально; поддержка 1.2 через WB оговорена выше |
| Точная задача + генерация | Многоэтапная задача о резервуаре с эталоном 690 + одна идея ролика про бытовые привычки |
| По пять повторов | Шесть комбинаций, 30 независимых запросов, одинаковые промпты и остальные параметры |
| Различия между повторами | Уникальные исходные ответы, валидные JSON и нормализованные идеи |
| Сбои формата и неверные ответы | Раздельные счётчики; ошибки API и исключённые ответы тоже отдельно |
| Где разнообразие полезно или вредит | Итоговый ИИ-разбор с примерами конкретных повторов |
| Назначение каждой температуры | Ориентиры и выводы ИИ по результатам, с ограничениями интерпретации |
| Одинаков ли ответ при 0 | Фактическое посимвольное сравнение пяти ответов, даже если формат нарушен |
| Примеры и выводы | Все 30 ответов в Markdown и исходный JSON; нужны новый прогон и успешный ИИ-разбор |
| Видео + код | `main.py` и запись запуска `results/demo.mp4` |
