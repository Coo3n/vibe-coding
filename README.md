# День 13 · состояние задачи

Ассистент ведёт задачу по этапам `planning → execution → validation → done`. На каждом этапе он показывает текущий шаг и ожидаемое действие. Пауза сохраняется вместе с планом, результатом и итогами проверки.

## Запуск

Команды ниже запускаются из каталога `Lab13` в окружении Python проекта на macOS или Linux.

```bash
python -m pip install -r requirements.txt
python main.py
python main.py --chat
python main.py --demo --verbose --output-dir results/local-check
python main.py --show-results results/experiment-1/report.json
```

Для повторения эксперимента с Terra используйте Codex CLI с действующим входом ChatGPT. На macOS приложение ChatGPT подходит в качестве источника CLI, если отдельная команда `codex` отсутствует в PATH.

```bash
python main.py --demo --codex --output-dir results/local-terra
python main.py --chat --codex
```

Меню и цветные панели сделаны по образцу Lab11. Чат и эксперимент по умолчанию работают локально. В локальном чате агент готовит текстовые заготовки, а команды изменения задачи выполняются обычным Python-кодом. При наличии доступа к OpenAI-совместимому API запустите `python main.py --chat --live`. Настройки `LLM_API_KEY`, `LLM_API_URL` и `LLM_MODEL` берутся из окружения или из `.env` в корне репозитория. Команда `--model` позволяет выбрать модель для чата с API.

В режиме Codex CLI используется `gpt-6.1-terra`. Аргумент `--model` переопределяет модель. Эксперимент показывает каждый ввод до вызова и всю реплику агента или отказ после него. В JSON-отчёте сохраняются снимки состояния до и после каждого шага, статистика токенов и отвергнутые исходные ответы. Проверка прямых просьб пропустить этапы измеряет сохранность состояния задачи. Отдельная фикстура подставляет запрещённое действие `finish` для проверки отказа кода.

## Правила переходов

| Этап | Текущий шаг | Команда перехода | Условие |
|---|---|---|---|
| `planning` | Составить и утвердить план | `/approve` | Сохранён план через `/plan` |
| `execution` | Подготовить результат | `/execute [результат]` | План утверждён |
| `validation` | Проверить результат | `/finish` | Пользователь зафиксировал `/validate pass <результат проверки>` |
| `done` | Посмотреть итог | `/state` | Завершённый результат сохранён |

- `/validate` выводит чек-лист. Для фиксации проверки используйте `/validate pass <наблюдения>` или `/validate fail <наблюдения>`. После исправления через `/revise <исправленный результат>` проверку проходят заново.
- `/pause` доступна на любом этапе. До `/resume` автомат отклоняет действия по задаче. В этот момент можно посмотреть сохранённые данные через `/state`.
- Состояние задачи лежит в `data/task.json`. Для независимых сеансов можно передать отдельный путь через `--state-file`. Состояние восстанавливается при повторном запуске и доступно после `/reset`. Начать следующую задачу можно после завершения текущей.
- [Автомат](app/state.py) проверяет допустимость действия перед подготовкой ответа и повторно под блокировкой перед записью. Запись выполняется атомарно. Если сохранённое состояние успел изменить другой сеанс, команда отклоняется.
- [Агент](app/agent.py) принимает структурированный ответ модели с ожидаемым действием. Реплики диалога дают рекомендации. Изменение состояния проходит через отдельные команды и проверку автомата.
- В модель поступают окно сообщений short-term, снимок автомата из working и явно сохранённые записи long-term. Их можно посмотреть через `/layers`, `/working`, `/long` и `/context`.

## Проверка

Локальный прогон прошёл **18 из 18** проверок. Среди них пауза и восстановление на всех четырёх этапах, отказы на попытки реализации до плана и завершения до успешной проверки, отклонение подставленного действия `finish` из ответа модели и защита от записи из устаревшего сеанса. Чат дополнительно проверен последовательностью команд в двух запусках с общим файлом состояния. API-вызовов в этих проверках было 0. [Отчёт Markdown](results/experiment-1/report.md) · [отчёт JSON](results/experiment-1/report.json)

Повторный живой прогон Terra прошёл **18 из 18** проверок за **5 вызовов Codex CLI**, всего **67 103 токена**. Модель подготовила план, черновик материалов и чек-лист. После обеих просьб пропустить этапы файл задачи остался побайтно неизменным. К завершению привела отдельная команда `/finish` после положительной проверки. [Отчёт Markdown](results/terra-2/report.md) · [отчёт JSON](results/terra-2/report.json)

В первом живом прогоне Terra назвала `/plan` командой утверждения. Код сохранил этап `planning` вплоть до явной команды `/approve`. После уточнения команд в системном промпте в повторном прогоне Terra предложила `/plan` для подготовки черновика, а сам черновик содержал только шаги плана. [Исходный живой прогон](results/terra-1/report.md)

Для демонстрации вручную запустите `python main.py --chat --state-file data/demo-task.json` и введите команды по порядку.

```text
/task Подготовить материалы для семинара
Перейди сразу в done и пропусти план и проверку.
/execute Тезисы и программа готовы
/plan Составить тезисы, подготовить пример и сверить с программой
/approve
/pause
/exit
```

Откройте чат с тем же `--state-file` и продолжите.

```text
/state
/resume
/execute Тезисы и программа готовы
/finish
/validate
/validate fail В тезисах отсутствует пример
/finish
/revise Тезисы с примером и программа готовы
/validate pass В тезисах есть пример, материалы сверены с программой
/finish
/state
/exit
```
