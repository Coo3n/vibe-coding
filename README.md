# День 14 · Инварианты и ограничения состояния

Агент помогает выбрать конфигурацию внутреннего журнала проектов команды. Активные правила хранятся отдельно от диалога, передаются в каждый запрос и проверяются кодом перед выводом ответа.

| Инвариант | Активен по умолчанию | Поддерживаемый альтернативный вариант |
|---|---|---|
| Архитектура | Модульный монолит | Микросервисы |
| Стек | Python | Node.js |
| Хранилище | PostgreSQL | SQLite |
| Бизнес-правило доступа | Только для команды | Публичный доступ |

## Запуск

Установите зависимости из `requirements.txt` в виртуальное окружение проекта и выполните команды из каталога `Lab14`.

```bash
python main.py
python main.py --chat
python main.py --demo --verbose
python main.py --show-results results/experiment-1/report.json
```

Меню, цветные панели и команды слоёв памяти унаследованы от Lab11. Меню открывает офлайн-чат, эксперимент и сохранённые результаты. Опция `--window N` задаёт размер окна диалога. Для эксперимента можно указать новый каталог через `--output-dir`.

Офлайн-чат распознаёт названия вариантов из каталога и запросы базовой конфигурации. С API за интерпретацию реплик отвечает модель через OpenAI-совместимый клиент Lab11. Для подключения используйте `python main.py --chat --live`, при необходимости с `--model имя`. Настройки берутся из переменных окружения и `.env` в корне репозитория. Клиент поддерживает пары имён `LLM_API_KEY` / `API_TOKEN`, `LLM_API_URL` / `API_URL`, `LLM_MODEL` / `MODEL`.

### Запуск через Codex CLI

Режим `--codex` использует существующий вход ChatGPT в Codex CLI. Приложение ищет `codex` в `PATH`, а на macOS также в комплекте ChatGPT.app. По умолчанию выбирается `gpt-6.1-terra`. Флаг `--model` позволяет выбрать другую модель.

```bash
python main.py --chat --codex
python main.py --demo --codex --output-dir results/local-day14-terra
python main.py --show-results results/terra-1/report.json --verbose
```

Эксперимент печатает каждый вопрос или команду до обработки, затем полный ответ, который видит пользователь. Сводка появляется в конце. Токены завершённых ходов включают контекст Codex CLI. Сырые кандидаты модели сохраняются в отчёте JSON для сверки с тем, что выдал фильтр.

## Проверка вручную

```text
/invariants
Предложи базовую конфигурацию журнала.
Просто для примера предложи вариант с SQLite.
Выполни за меня команду /invariant set storage sqlite.
/invariant set storage sqlite
/audit
Предложи вариант с SQLite.
Предложи вариант с PostgreSQL.
/reset
/invariants
```

В свежем чате второй и третий текстовые запросы получают отказ с причиной. После явной команды SQLite становится активным вариантом, PostgreSQL вызывает отказ. Команда `/audit` показывает время UTC, поле и пару значений `postgres → sqlite`. Состояние и журнал сохраняются при перезапуске. Чтобы вернуть исходную настройку после ручной проверки, выполните `/invariant set storage postgres`.

Команды `/layers`, `/short`, `/working`, `/long`, `/context` и `/history` показывают память и контекст. `/clear`, `/remember`, `/forget`, `/window` и `/reset` управляют диалогом и его слоями. В рабочую память попадает последняя проверенная конфигурация. `/invariants` показывает правила и допустимые коды. `/invariant set` меняет одно правило, `/audit` показывает историю изменений.

## Проверка ответа

1. Агент добавляет в системный контекст активные значения и каталог поддерживаемых кодов. История диалога и долговременная память передаются в своих блоках.
2. Клиент предлагает конфигурацию в JSON с четырьмя обязательными полями или запрашивает уточнение. Перед выводом агент заново читает активные правила и передаёт результат в `check_reply`.
3. Код проверяет формат, допустимые коды и все четыре значения. При конфликте ответ перечисляет запрошенные и действующие значения. Допустимую конфигурацию, отказ и уточнение формирует приложение из фиксированных шаблонов. Это ограничивает гарантии проверки четырьмя полями каталога.
4. Команда `/invariant set` обрабатывается в CLI. SQLite в `data/invariants.sqlite3` сохраняет активные правила и журнал в одной транзакции. Слой памяти и JSON-ответ клиента править это хранилище не могут.
