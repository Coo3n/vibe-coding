# День 11 · Модель памяти ассистента

## Задача

Разделить память ассистента на три слоя, хранящихся отдельно:

| Слой | Что хранит | Как обновляется | Правило попадания в промпт |
|---|---|---|---|
| `short-term` | Сообщения текущего диалога (список) | Каждая реплика добавляется | Последние N сообщений дословно (окно, по умолчанию 4); текущая реплика — всегда |
| `working` | Данные текущей задачи: цель, даты, бюджет, ограничения, договорённости (словарь) | Автоматически: служебный LLM-вызов после каждой реплики пользователя | Весь словарь как system-блок «Данные текущей задачи» |
| `long-term` | Профиль, решения, знания (словарь на диске `data/long_term.json`) | Только явно: `/remember`, `/forget` и сид фактов Дня 10 | Весь словарь как system-блок «Долговременная память» |

Промпт собирается методом `MemoryStore.context()`: system-инструкция → блок
long-term → блок working → окно последних N сообщений. Каждый блок помечен
своим заголовком, поэтому вклад слоя измерим отключением блока.

Основа long-term — facts Дня 10: решения по японской поездке (страна, даты
12–26 апреля, вылет из СПб, бюджет 250 тыс. руб/чел, аллергия на морепродукты,
друг-вегетарианец, Токио→Киото (Гион), Нара, без капсульных отелей, вылет
из Осаки, JR Pass, виза до 20 марта). Файл `data/long_term.json` переживает
перезапуск процесса и `/reset`.

Явность сохранений:

- `long-term` меняется только командами `/remember <текст>` (или `ключ: значение`)
  и `/forget <ключ>` — плюс явный сид фактов Дня 10 в начале эксперимента;
- `working` обновляется автоматически, но это отдельный служебный вызов, чей
  расход (`side_tokens`/`side_calls`) считается честно и виден в отчёте;
- `short-term` — просто история, окно управляется `/window N`.

## Результаты

### Codex CLI · Terra

Прогон на **`gpt-6.1-terra`** завершился с 60 основными и 47 служебными
вызовами. Полный контекст дал 9/9 правильных ответов, без short-term
получилось 8/9, без working — 7/9, без long-term в том же диалоге — 9/9.
В новом диалоге сохранились 4/4 ответа. После явного `/remember` и `/reset`
агент ответил на 2/2 вопроса, а после очистки long-term — на 0/4.

Входной контекст сократился на 1 063 токена без short-term, на 295 без
working и на 247 без long-term. Общий расход 1 391 672 токена включает
служебный контекст Codex.

[Отчёт Terra](results/terra-1/report.md) · [Ответы и метрики](results/terra-1/report.json)

### Прямой API · архив

Сохранённый прогон через прямой API: модель **`glm-5.3`**, окно **4 сообщения**,
8 ходов диалога + 2 новых решения, замер токенов слоёв, 9 контрольных вопросов
в 4 конфигурациях ablation, 4+2 вопроса после `/reset` и финальная очистка
long-term. Всего 116 722 токена: 60 основных и 47 служебных вызовов
(служебные — 57 078 токенов).

#### Токены каждого слоя

Замер на репрезентативном запросе «Какой у нас бюджет на человека?» из одинакового
состояния слоёв: дельта `prompt_tokens` при отключении слоя по одному.

| Слой | Токенов на запрос | За прогон (оценка¹) | Доля полного промпта |
|---|---:|---:|---:|
| long-term | 221 | 13 260 | 18,0% |
| working | 424 | 25 440 | 34,6% |
| short-term (окно 4) | 530 | 31 800 | 43,3% |
| полный промпт | 1225 | — | 100% |

Сопровождение working-памяти — цена служебных вызовов после реплик диалога,
измерено точно: **11 170 токенов в 10 вызовах** (после 10 реплик). Поддержка
слоя стоит дороже, чем он добавляет в один запрос: ~1 117 токенов на реплику
против 424 токенов самого блока.

¹ Оценка: токены слоя на репрезентативном запросе × 60 основных вызовов прогона.
Реальный вклад растёт вместе со слоями — это способ сравнения, а не тарификация.

#### Ablation: очистка слоёв по очереди

После диалога состояние слоёв восстанавливается из снимка, один слой отключается
из промпта, одни и те же вопросы задаются заново.

| Конфигурация | Детали | Сломавшиеся вопросы |
|---|---:|---|
| Полный контекст | 9/9 | — |
| Без short-term | 8/9 | Что мы собираемся делать в Наре? |
| Без working | 7/9 | Район Токио вечером?; Сколько закладываем на еду в день? |
| Без long-term (тот же диалог) | 9/9 | — |
| Новый диалог после /reset | 4/4 | — |
| После /remember и /reset | 2/2 | — |
| Новый диалог без long-term | 0/4 | все четыре вопроса |

[Отчёт и разбор ответов](results/experiment-1/report.md) · [Полные ответы и метрики](results/experiment-1/report.json)

#### Выводы

- **Слои дублируют друг друга — и это спасает при сбое одного.** В том же диалоге
  отключение long-term ничего не сломало (9/9): факты Дня 10 повторялись в working
  и окне short-term. Отключение одного слоя деградирует мягко: −1 вопрос (short),
  −2 вопроса (working).
- **У каждого слоя — свои незаменимые данные.** Без short-term потерялась деталь
  свежей реплики (что делать в Наре). Без working потерялись новые решения
  (Синдзюку, 3000 иен/день): они уже выпали из окна и не были явно записаны
  в long-term. Это зона ответственности working.
- **После /reset работает только long-term — и он справился: 4/4.** Вопросы
  «Куда мы ездили в апреле?» и «Какой у нас бюджет?» отвечаются исключительно
  из долговременной памяти с фактами Дня 10.
- **Явное сохранение работает и незаменимо.** `/remember` двух новых решений
  перед `/reset` — и они пережили новый диалог (2/2). Без long-term после
  `/reset` агент честно отвечает «данных нет» на все вопросы (0/4).
- **Цена памяти.** Самый дорогой в промпте слой — окно short-term (43% промпта),
  но оно gratis. Working добавляет 35% промпта плюс ~1 117 токенов служебных
  вызовов на реплику. Long-term — самый дешёвый (18%) и единственный, кто
  переживает `/reset`: лучшая покупка за токен в этой архитектуре.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

Для подключения API задайте `API_TOKEN`, `API_URL` и `MODEL` в окружении
или в `.env` в корне репозитория. Сохранённый отчёт открывается без этих настроек.

```bash
python main.py --demo
python main.py --chat --window 6
python main.py --demo --output-dir results/my-run
python main.py --show-results results/experiment-1/report.json
python main.py --demo --codex
python main.py --chat --codex
python main.py --show-results results/terra-1/report.json
```

Без аргументов открывается меню. Перед первой репликой эксперимент показывает
исходные факты Дня 10 и состояние рабочей и краткосрочной памяти. Этот снимок
также записывается в отчёт. Полный текст запроса выводится
перед вызовом модели, а ответ и расход токенов появляются после завершения шага.
`--codex` использует вход в Codex CLI и модель `gpt-6.1-terra` по умолчанию.
Модель можно указать через `--model имя`. Общий расход в этом режиме включает
служебный контекст Codex, а вклад слоёв оценивается по дельтам внутри прогона.

Эксперимент записывает начальные факты и выполняет очистку в файле
`long_term.json` внутри папки результатов прогона. Ручной чат хранит
долговременную память в `data/long_term.json`.

## Команды чата

```text
/layers                    — сводка по всем слоям
/short · /working · /long  — содержимое слоя
/clear short|working|long  — очистить слой (long-term перезаписывает файл)
/remember ключ: значение   — явно записать в long-term (переживает /reset)
/forget ключ               — удалить запись из long-term
/context                   — промпт, который собирается из слоёв прямо сейчас
/history                   — полная история short-term
/window N                  — размер окна short-term
/reset                     — новый диалог: short и working очищаются, long-term остаётся
/help · /exit
```

Пример переноса решения в долговременную память:

```text
Решили, что на еду тратим до 3000 иен в день.
/remember еда: до 3000 иен в день на человека
/reset
Сколько мы закладываем на еду в день?   → отвечает long-term
```

## Методика и ограничения

- Слои хранятся отдельно: short-term и working — в процессе, long-term — в
  `data/long_term.json` на диске. `/reset` очищает только short и working.
- Токены слоя измерены честно: на репрезентативном запросе из одинакового
  состояния слоёв замеряется `prompt_tokens` полного контекста и контекста
  без одного слоя; дельта = вклад слоя. «За прогон» — оценка: токены слоя ×
  число основных вызовов; реальный вклад растёт вместе со слоями.
- Цена поддержки working — служебные вызовы после реплик; их расход посчитан
  отдельно (`side_tokens`) и не входит в колонку «На запрос».
- Ablation: после диалога состояние слоёв восстанавливается из снимка, один
  слой отключается из промпта, пробные вопросы задаются заново. Оценка ответов
  по ключевым словам (совпадение + отсутствие denial-маркеров) приблизительная,
  полные ответы для сверки — в `report.json`.
- Счётчик вызовов — логические запросы к API, не сетевые попытки. При отсутствии
  `usage.total_tokens` прогон останавливается: неизвестный расход не нулевой.

Код: `app/cli.py` — консоль; `app/memory.py` — три слоя и сборка промпта;
`app/agent.py` — диалог поверх памяти; `app/scenario.py` — сценарий и сид
long-term; `app/experiment.py` — эксперимент; `app/report.py` — отчёты;
`app/client.py` — прямой API, `app/codex_client.py` — Codex CLI. Точка входа — `main.py`.
