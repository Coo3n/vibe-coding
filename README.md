# День 8 · Токены и контекст

## Выводы эксперимента

Расход указан **в токенах, не в деньгах**: тариф API ВБ неизвестен.

| Сценарий | Ходов / API-запросов | Вход: первый → последний ход | Рост входа | Общий расход¹ |
|---|---:|---:|---:|---:|
| Короткий | 1 / 1 | 2104 → 2104 | — | 2743 |
| Длинный | 6 / 7 | 2104 → 5189 | +3085; ×2,47 | 28890 |
| Нагрузочный² | 24 / 47 | 2141 → 172663 | +170522; ×80,65 | 4107482 |

¹ Вход + выход всех запросов, включая проверки памяти. Суммарный расход длинного
сценария в **10,53 раза** больше короткого; это расход всего сценария, не одного запроса.
² Снимок последнего сохранённого прогона: 24 хода и 23 проверки памяти.
История пополняется искусственными учебными материалами примерно по 7000 токенов,
поэтому сравнение показывает влияние объёма, а не одинаковую нагрузку трёх сценариев.

- **Прирост:** в нагрузочном сценарии последние ходы добавляли около 7300 токенов:
  новое сообщение, предыдущий ответ и служебные записи. Старая история передавалась заново.
- **Память:** после 23 ходов при входе 165705 токенов все **7/7 проверок верны**.
  Это проверка заданных фактов, изменений и неизвестных значений, не доказательство
  отсутствия любых галлюцинаций.
- **Переполнение:** в предыдущем завершённом прогоне три факта сохранились при входе
  242152 токена. На 34-м ходу сервер отказал: окно 262144, резерв ответа 16192,
  для входа остаётся 245952 токена. При отказе ответа модели нет.
- **Главный вывод:** длинная передаваемая история увеличивает вход каждого запроса
  и накопленный расход. Полную переписку можно хранить в файле, но бесконечно
  передавать её целиком нельзя. Сжатие истории в этом эксперименте не проверялось.

Агент подбора путёвок: сравнение расхода токенов в коротком, длинном и растущем до лимита диалоге.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

В `.env` укажите `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL=coder-mini`.
API должен поддерживать OpenAI-совместимые chat completions, tools и JSON Schema.
При первом запуске токенизатор скачивается с Hugging Face.

В меню: **1** — все кейсы, **2** — короткий, **3** — длинный,
**4** — предел контекста, **5** — ручной чат. В PyCharm достаточно запустить `main.py`.

```bash
python main.py --case 3 --model coder-mini  # только нагрузочный сценарий
```

## Что проверяем

- **Короткий:** один ход.
- **Длинный:** шесть ходов с поиском и воспоминанием результатов.
- **Предел:** вся история сохраняется; каждый ход добавляет около 7000 токенов
  вымышленных учебных материалов. После каждого хода — отдельная проверка памяти.
  Остановка при ошибке API или после 80 ходов; прогон выполняет реальные запросы.

Семь проверок: код заявки, страна, первоначальный и изменённый бюджеты,
место встречи, город вылета и неизвестный PIN. Не сообщённые значения должны
остаться `null`. Ответы проверок не попадают в основной диалог.
Ошибки памяти не инсценируются; отказ API по лимиту — не галлюцинация.

## Как читать токены

- **Контекст на входе:** история, новое сообщение, инструкции и инструменты первого запроса хода.
- **Прирост:** изменение этого входа относительно предыдущего хода.
- **Расход за ход:** вход + выход всех API-запросов хода.
- **Расход с начала:** сумма по сценарию, включая проверки памяти; это не размер контекста.
- **Размеры сообщения и истории:** локальный подсчёт, не дополнительный расход.
- **`?`:** API не сообщил usage; неизвестное не считается нулём.

История пересылается повторно, поэтому накопленный расход растёт быстрее её размера.
Кэшированные входные токены уже входят в usage. Денежная стоимость не рассчитывается.
Каталог сообщал окно 150000, ошибка сервера — 262144: проценты по каталогу не показываются.

## Файлы результатов

Подробные трассировки сохраняются локально в `results/tokens-*/demo.json` и не входят в Git.
Демо изолировано от ручного чата. Чат сохраняется в `data/session.json`;
команды: `/new`, `/history`, `/exit`. Каталог путёвок вымышленный.
