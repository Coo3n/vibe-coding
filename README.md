## Задача лабораторной

Сравнить память и расход токенов агента при передаче всей истории и при её периодическом
сжатии. Агент помогает запустить овощной онлайн-прилавок: согласует ассортимент, бюджет,
сроки и доставку, рассчитывает закупку. Python CLI использует реальные запросы
к OpenAI-совместимому API, строгий JSON и настоящие вызовы инструментов.

## Результаты

В обоих сравниваемых диалогах — модель `coder-medium`, 50 ходов
(100 видимых сообщений) и 20 независимых проверок памяти. Пользовательские сообщения
совпадают, ответы агента сгенерированы отдельно и могут различаться.
Во втором эксперименте история сжимается после ходов **10, 20, 30, 40 и 50**,
последние **8 сообщений** сохраняются дословно.

| Показатель | Без сжатия | Со сжатием |
|---|---:|---:|
| Точно воспроизведённые контрольные детали | **20/20** | **20/20** |
| Диалог | 407 506 | 224 792 |
| Создание summary | 0 | 54 908 |
| Проверки памяти | 270 219 | 73 051 |
| **Полный расход, токены** | **677 725** | **352 751** |

**Экономия полного теста: 324 974 токена, или 47,95%.** Все пять summary уже включены
в итог второго эксперимента. На самом диалоге с учётом summary экономия составила
**31,36%**, на последующих проверках памяти — **72,97%**.

Источники:
- **Эксперимент 1:** [отчёт](results/experiment-1/report.md), [исходная трассировка](results/experiment-1/report.json).
  Запускался режим `both`: часть без сжатия завершилась, последующая попытка со сжатием
  оборвалась на 40-м ходе. В таблице выше взята только завершённая часть без сжатия.
  Полный расход того запуска — 895 218 токенов — включает и неудачную попытку.
- **Эксперимент 2:** [отчёт](results/experiment-2/report.md), [исходная трассировка](results/experiment-2/report.json).
  Отдельный запуск со сжатием завершился полностью.

### Выводы по лабораторной

1. **Сжатие уменьшает расход:** в этом сравнении полный тест потребовал почти вдвое
   меньше токенов. Выгода особенно заметна при повторных вопросах к накопленной истории.
2. **Проверяемые факты сохранились:** оба режима дали 20/20 точных совпадений.
   Это результат конкретного сценария, а не гарантия сохранения любой информации.
3. **Вход после сжатия действительно падает:** например, между ходами 40 и 41 второго
   эксперимента — с **6 139 до 3 997 токенов**. Между сжатиями он снова растёт,
   потому что добавляются новые сообщения. Накопительный счётчик потраченных токенов
   всегда растёт: сжатие не возвращает уже израсходованные токены.
4. **Summary тоже растёт:** размер его JSON увеличился с **1 733 до 6 314 символов**.
   Просьба уложиться в 250 слов не является жёстким ограничением. Следующее улучшение —
   ограничить объём памяти и отсеивать общие советы, повторы и неактуальные сведения.
5. **Сжатие имеет цену и может завершиться ошибкой:** в первом запуске четвёртая попытка
   исчерпала 16 192 выходных токена на рассуждения и не вернула JSON summary.
   Повторный запуск прошёл успешно, но это показывает необходимость обработки такого сбоя.

Итог: **summary + короткий хвост — рабочий способ снизить расход при сохранении важных
договорённостей**, однако нужно контролировать размер summary и надёжность его создания.
Проценты относятся к токенам, а не к денежной стоимости API; независимая генерация
ответов также влияет на разницу между запусками.

## Запуск

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

В `.env`: `LLM_API_URL` (полный адрес `/chat/completions`), `LLM_API_KEY`, `LLM_MODEL`.
Файл с ключом не входит в Git. API должен поддерживать tools, `tool_choice=required`,
JSON Schema и `strict=true`.

В меню: **1** — автотест без сжатия, **2** — со сжатием, **3** — оба подряд,
**4 / 5** — ручной чат со сжатием / без сжатия. В PyCharm достаточно запустить `main.py`.

```bash
python main.py --case full                    # только без сжатия
python main.py --case compressed              # только со сжатием
python main.py --case both                    # два диалога и сравнение
python main.py --case both --verbose          # полные реплики и tool calls
python main.py --demo --turns 15              # короткий вариант: 30 сообщений
python main.py --chat --keep-last 8 --compress-every 20
python main.py --chat --mode full
```

`--compress-every 20` — интервал 20 видимых сообщений, то есть 10 ходов.
Интервал и размер хвоста — положительные чётные числа. Для изменения настроек ручного
чата используйте новый `--session путь.json`. Каталог `--output-dir` для автотеста
должен быть новым.

## Инструменты и формат

| Инструмент | Назначение |
|---|---|
| `get_products` | Учебный каталог овощей, цены и остатки |
| `calculate_batch` | Проверка количества и остатков, расчёт закупки, упаковки и доставки на Python |
| `respond_to_user` | Финальный ответ: JSON с `answer`, `questions`, `next_step` |

Модель выбирает инструменты и аргументы через `tool_calls`. В чат-запросах используется
`tool_choice=required`, включая финальный ответ. Цены учебные, инструменты не оформляют заказы.
Обычный текст пользователя оборачивается в `{"message": "…"}`. Аргументы, результаты,
ответы, summary и проверки памяти — JSON с локальной валидацией.

## Как устроено сжатие

После каждых 10 завершённых ходов сообщения старше хвоста отправляются той же LLM
вместе с предыдущим summary. Модель возвращает `facts`, `decisions`, `open_questions`.
Только после валидации старые ходы заменяются новым summary. В очередной запрос идут
системная инструкция, summary и несжатый хвост.

Видимое сообщение — реплика пользователя или финальный ответ агента. Вызовы tools
не сдвигают расписание, но сохраняются вместе со своим ходом: вызов и результат
не разрываются. Между сжатиями хвост растёт; сразу после сжатия остаётся 8 сообщений.

Сессии сохраняются атомарно в `data/session-compressed.json` и `data/session-full.json`.
При ошибке API, JSON или сохранения ручной ход не фиксируется.
Команды чата: `/summary`, `/history`, `/new`, `/exit`.

## Методика и учёт токенов

До диалога фиксируются 20 контрольных деталей: имя, название, бюджеты, сроки,
поставщик, доставка, упаковка, оплата и другие договорённости. Каждый вопрос проверки
получает независимую копию конечного контекста; инструменты недоступны, эталоны модели
не передаются. Все контрольные детали успевают покинуть несжатый хвост.
Несовпадение формулировки помечается для сверки и не обязательно означает забывание.

Терминал показывает вход и его изменение, расход запроса и накопленный расход запуска.
Синий — без сжатия, зелёный — со сжатием, жёлтый — summary, красный — ошибка или
ответ для сверки. `--verbose` раскрывает полные сообщения.

**Полный расход = диалог + summary + проверки памяти.** Каждый запрос учитывается
один раз, включая служебные вызовы. Используется фактический usage API; неизвестный
usage обозначается `?`. Кэшированные токены уже входят во вход.

Каждый запуск сохраняет `report.json` с трассировками и `report.md` с результатами.
JSON обновляется после каждого шага, в том числе неудачного. Локальные прогоны
`results/local-*/` игнорируются Git; в репозиторий включены два выбранных эксперимента.

Код: `app/agent.py` — цикл tools; `app/context.py` — история и summary;
`app/protocol.py` — JSON-схемы; `app/scenario.py` — сценарий и эталоны;
`app/experiment.py` — эксперимент; `app/tokens.py` — учёт токенов;
`app/tools.py` — каталог и расчёт; `app/cli.py` — терминал.
