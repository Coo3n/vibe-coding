# Контроль ответа LLM

🎥 [Видео демонстрации эксперимента](results/demo.mov)

Эксперимент: один длинный запрос о карьере инженера в эпоху ИИ, пять независимых режимов, по три «холодных» запроса на каждый. История диалога не передаётся. Используется OpenAI-совместимый Chat Completions API.

| Режим | Единственное добавленное ограничение |
| --- | --- |
| `baseline` | Нет |
| `format` | Системная инструкция вернуть JSON `{"tips": [{"title": "...", "explanation": "..."}]}` |
| `max_tokens` | `max_tokens=128` |
| `stop` | `stop=["."]` — останавливает ответ перед первой точкой |
| `schema` | `response_format.type=json_schema`, `strict=true` |

Текст пользовательского запроса одинаков во всех режимах. Ответы проверяются без исправлений: `json.loads` — синтаксис, `jsonschema` — ровно три совета с обязательными строковыми полями без лишних ключей.

## Запуск

Установите зависимости: `python -m pip install -r requirements.txt`. Создайте `.env`:

```dotenv
LLM_API_KEY=ваш_ключ
LLM_API_URL=https://api.example.com/v1/chat/completions
LLM_MODEL=идентификатор_модели
```

```bash
python main.py                         # 3 прогона на режим
python main.py --runs 5 --max-tokens 96
```

Консоль показывает таблицу и **полный ответ каждого прогона** с результатом проверки; секции «ИТОГ» нет. JSON с запросами, ответами, `finish_reason`, расходом токенов и сводкой сохраняется в `results/`. При сетевой ошибке или HTTP 401/403/429 эксперимент останавливается и сохраняет уже полученные данные.

## Проверенный прогон

Локальный отчёт `results/20261107T165101807474Z.json` (JSON-отчёты не добавляются в Git): 15 ответов модели `coder-medium`, без ошибок API.

| Режим | JSON / схема | Наблюдение |
| --- | --- | --- |
| Без ограничений | 0/3 · 0/3 | Обычный текст и Markdown |
| Явный формат | 3/3 · 3/3 | Корректная структура |
| Лимит 128 | 0/3 · 0/3 | Все ответы оборвались (`finish_reason=length`) |
| Stop `.` | 0/3 · 0/3 | Ответы завершились через 50, 28 и 3 токена |
| Строгая схема | 3/3 · 3/3 | Корректная структура |

Отсутствие JSON в режимах лимита и stop не доказывает, что виноваты только они: в этих режимах JSON не запрашивался. Три прогона — примеры поведения, а не оценка надёжности модели; валидный JSON не доказывает смысловую правильность или реальную поддержку `strict` провайдером.
