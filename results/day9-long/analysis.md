# Длинный автономный прогон: память и токены

## Что выполнено

- 30 сообщений пользователя + 30 финальных ответов агента = **60 видимых сообщений**.
- **94 записи** вместе со служебными tool calls/results.
- Настоящие вызовы `get_products`, `calculate_batch`, `respond_to_user`.
- **5 сжатий** после 18, 28, 38, 48 и 58 видимых сообщений.
- В конце summary + **10 видимых сообщений / 15 записей**, совпадающих с исходным хвостом.
- Все 20 контрольных деталей сообщены в первых 15 ходах; после пяти сжатий эти ходы
  отсутствуют в хвосте. Проверки не получают инструментов и эталонных ответов.
- **40 независимых проб**, по 20 к каждому контексту. Полная и сжатая версии построены
  из одной и той же реальной переписки; вопросы не освежают память друг друга.

## Память: автоматическая оценка и сверка формулировок

Полная история: **20/20** точных совпадений.
Сжатая история: **17/20** точных совпадений с заранее заданными вариантами.
При проверке трёх несовпадений все они оказались корректными перефразировками:

| Деталь | Ответ со сжатием | Разбор |
|---|---|---|
| Район | Приморский район СПб | СПб — сокращение Санкт-Петербурга; район сохранён |
| Упаковка | Бумажные пакеты (пластиковые одноразовые запрещены) | Выбранная упаковка указана точно, добавлено согласованное ограничение |
| Запрет | Пластиковые одноразовые пакеты | Те же признаки и предмет запрета, изменён только порядок слов |

Таким образом, **по смыслу сохранены 20/20 деталей в обоих режимах**. Наблюдаемых
потерь контрольных фактов в этом прогоне нет. Автоматические баллы не переписывались,
эталон после прогона не расширялся. Отдельная сверка записана в `assessment.json`.

Это отличается от короткого baseline, где пропал итог закупки. Каждый прогон заново
генерирует ответы и summary: длинный не является продолжением короткого. Поэтому
разницу нельзя объяснять только количеством сообщений. Внутри каждого прогона
сравнение контролируемое — исходная переписка одинакова для двух режимов.

## Фактический usage

| Этап | Запросов | Токенов |
|---|---:|---:|
| Общая подготовка диалога, включая tools | 32 | 151712 |
| Создание summary | 5 | 19001 |
| Проверки полной истории | 20 | 154587 |
| Проверки сжатой истории | 20 | 59007 |
| Проверки сжатой истории + summary | 25 | 78008 |
| Весь фактический эксперимент | 77 | 384307 |

Экономия проверок с учётом summary: **76579 токенов / 49,54%**.
С общей подготовкой: **306299 → 229720**, экономия **25,00%**.

Это стоимость обращений к готовой полной или сжатой истории. Генерация второго
независимого диалога не измерялась. В строку всего эксперимента не входят прошлый
короткий прогон и диагностические вызовы. Денежный тариф API неизвестен.

## Вывод

Повторные запросы к сжатому контексту заметно дешевле даже с учётом пяти запросов
на summary. Все проверенные детали в этом прогоне доступны после сжатия.
Сжатие не гарантирует ни потери, ни идеальной памяти — короткий baseline показывает
возможную потерю результата инструмента. На оценку также влияет метод сравнения:
точное совпадение строк нельзя без проверки называть числом забытых фактов.
