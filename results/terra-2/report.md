## Эксперимент 3 · пополнение профиля из диалога

Диалог в профиле «Кратко»: 2 вопроса → явная смена предпочтений → ещё 2 вопроса. Смена:

> Теперь отвечай подробно, показывай примеры кода и обращайся ко мне на Вы.

Изменения, извлечённые из реплики

- стиль: кратко → подробно
- формат: без кода → с кодом
- тон: неформально → формально
- ограничения += «обращаться на Вы»

| Этап | Стиль | Формат | Тон |
|---|---:|---:|---:|
| до смены | кратко · 1/2 | без кода · 2/2 | неформально · 0/2 |
| после смены | подробно · 2/2 | с кодом · 2/2 | формально · 2/2 |

Профиль, загруженный с диска после смены, совпадает с активным.

```json
{
  "имя": "Кратко",
  "стиль": "подробно",
  "формат": "с кодом",
  "тон": "формально",
  "ограничения": [
    "обращаться на Вы"
  ]
}
```

## Методика

Профиль добавляется после долговременной памяти отдельным сообщением system. Команда /prefer и обработка явных предпочтений в реплике обновляют JSON профиля. У каждого прогона временное хранилище.

Приблизительные пороги длины. «Кратко» — до 90 слов, «подробно» — от 150. «С кодом» — оформленный блок кода (только на вопросах, где код уместен), «без кода» — отсутствие блока; «формально» — заглавное «Вы»-обращение без эмодзи и «ты»-форм, «неформально» — «ты»-формы, разговорный маркер или эмодзи без «Вы»-обращения. Тон без явных маркеров остаётся вне критериев.

Разовые просьбы («покажи кодом» в одном вопросе) не должны менять профиль — извлекатель инструктирован отличать их от установок на будущее; срабатывания зафиксированы в отчёте.

Полные ответы сохранены в report.json.
